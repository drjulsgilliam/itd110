Storytelling Starter Review

The Nexora page and the storytelling starter use the same building blocks: a hero, three cards, a call to action and a footer. One was generated without anyone making a decision. The other was designed. Here is the difference, row by row, with code from each.

Nexora: assembled

Sections are there because landing pages usually have them. The words and pictures could belong to any product.

Starter: authored

Every section has one job in a story, every claim is backed by something on the page, and the code teaches what it does.

Color tokens

Nexora
bg-gradient-to-br from-violet-100
via-blue-100 to-indigo-100
from-violet-500 to-blue-500

The default AI gradient, hard-coded in class names on each element.

Starter
/* STEP 1: THE PALETTE */
--blue: #0071e3;
/* STEP 2: THE ROLES */
--color-accent: var(--blue);

Palette, then roles. Components use only role names, so one line restyles the site.

Why it matters: this is the difference between a page and a system. The "Try it" section turns that idea into something students can click.

Interaction JavaScript

Nexora
.card:hover { transform: translateY(-6px); }
.blob { animation: float 9s infinite; }

Motion as decoration: things lift and float because templates do that.

Starter
document.documentElement.style
  .setProperty('--color-accent',
               `var(${color})`);

One line of JavaScript changes one token, and a live readout (aria-live) shows the exact CSS that changed.

Why it matters: the interaction teaches the lesson of the page. Motion is the last step of the path, after layout works without it.

Typography type scale

Nexora

text-6xl · text-lg · text-sm

Inter because it's the default, sizes picked per element.

Starter
--font-body: -apple-system, … "Segoe UI",
             Roboto, …;
--text-hero: clamp(3rem, 2rem + 5vw, 6rem);
--width-text: 65ch;

The system stack is a stated choice (no download, native feel), with a fluid scale and a readable line length.

Why it matters: both may end up sans-serif. One is a decision with a reason written next to it.

Starter
aria-expanded="false" aria-controls="site-nav"
if (event.key === 'Escape') setMenu(false);

The menu announces its state and closes with Escape. Alt text is written for meaning, and motion respects user settings.

Why it matters: AI tools rarely add these unless asked. Knowing to ask is the skill.

The code itself maintainability

Nexora
<div class="rounded-2xl shadow-xl p-8
  hover:-translate-y-1 transition">

Utility-class soup with no comments. A student can copy it but can't learn from it.

Starter
1. TOKENS      design decisions
2. BASE        reset + global defaults
3. LAYOUT      reusable primitives
4. COMPONENTS  buttons, cards, header…
5. SECTIONS    story-specific styling
6. MOTION      the "dynamic" layer

One stylesheet, ordered by the cascade and commented throughout. The code is part of the lesson.

Why it matters: students will edit this page. Code they can read is code they can own.

A fair point to raise with students. The starter shares two surface traits with Nexora: a gradient on one headline word and a centered hero. That's fine. Good design isn't about avoiding every trend; it's about every choice having a reason. Here the gradient is a token you can change, and the centered hero sits above content that earns it.

The one-sentence version: AI can produce the shape of a website. Knowing what you're doing is what fills that shape with a story, real proof and decisions you can explain.
